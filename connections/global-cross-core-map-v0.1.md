# Global Cross-Core Connection Map v0.1

Status: **candidate typed interface map**  
Purpose: prevent five isolated operational libraries before mechanism-level expansion.

These are interface-level relationships, not yet a fully evidence-audited edge registry.

## Edge classes

- **system** — opportunity/enabling/environmental relation; no psychological state implied.
- **scientific_candidate** — plausible mechanism relation requiring claim-level evidence audit.
- **measurement** — observation/proxy relation with ambiguity.
- **learning** — account-local update/control relation.

## Feedback loops to preserve

### Loop A — Fit learning
Audience hypothesis
→ content choice
→ distribution
→ observed response
→ measurement validity
→ learning
→ revised audience hypothesis

### Loop B — Relationship accumulation
Repeated relevant encounters
→ HPC trust/connection/familiarity candidates
→ return/follow/participation
→ increased future encounter opportunity
→ additional relational evidence

### Loop C — Social transmission
Value/content response
→ transmission motive/action
→ network/platform exposure
→ new audience composition
→ new response data
→ learning

### Loop D — Distribution/content co-adaptation
Content packaging
→ platform/user response
→ distribution outcome
→ diagnosis
→ creative adaptation
→ new distribution test

### Loop E — Governance optimization
Observed outcomes
→ objective trade-off review
→ changed constraints/priorities
→ operational-core interventions
→ new outcomes

## Guardrails

1. No interface edge receives a numeric propagation weight by default.
2. "Candidate" means retrieval/reasoning target, not accepted causality.
3. System edges cannot auto-activate latent psychology.
4. Measurements must preserve competing explanations.
5. Platform-specific edges require freshness metadata.
6. Group/network-level variables must not be silently collapsed into individual psychological nodes.
